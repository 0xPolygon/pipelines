CI-only: `apps-npm-release.yml` now runs as five jobs, `version`, `build`, `attest`, `publish` and `finalize`, in place of the single `release` job. `build` packs unpublished public packages without any publish credential; `attest` records a build provenance attestation for each tarball; `publish` verifies each attestation against the calling repository, the released commit and ref, and this workflow's exact version, then uploads the tarballs through npm trusted publishing, and checks out and installs no repository code, using an exact pinned Node version; `finalize` creates the tags and GitHub Releases afterwards, only after `attest` and `publish` succeed when tarballs were packed, and fails if packages were published but no tags were created. A release with nothing public to publish skips `publish` and still tags. Job names change, so anything keyed on the old `release` job name needs updating. Callers must grant `attestations: write` in the trigger workflow's permissions before taking this change (`attest` writes attestations and `publish` reads them); without it the run fails at startup.
