CI-only: the release workflow conformance check now reports any workflow step, `with:` string, composite action or package script run from a workflow that fetches a package from the registry at run time (`npx`, `pnpm dlx`, `npm exec` and the like). `pnpm exec` stays allowed. In a job that holds a credential (`id-token: write`, an npm token or any secret other than `GITHUB_TOKEN`) it is an error that cannot be waived; elsewhere it is a notice for now. In such a job the check also reads the text of the step for a runner word the command parser did not confirm (a quoted argument, a heredoc, a prose input, a string inside script code), at any word boundary and after any flags. Only two forms are text and not commands, and only when their output cannot run later (not piped, not substituted, not eval'd, not passed to `xargs`, not redirected except to `$GITHUB_STEP_SUMMARY` or stderr): an `echo` or `printf` argument, and the pattern of a `grep`, `rg` or `sed`. A local action path with a `..` segment, in such a job, is reported as unreadable. `npm create`, `npm init <x>`, `pnpm create`, `yarn create` and `bun create` count as runners. It ships no package.
