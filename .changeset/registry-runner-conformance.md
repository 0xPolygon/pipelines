CI-only: the release workflow conformance check now reports any workflow step, `with:` string, composite action or package script run from a workflow that fetches a package from the registry at run time (`npx`, `pnpm dlx`, `npm exec` and the like). `pnpm exec` stays allowed. In a job that holds a credential (`id-token: write`, an npm token or any secret other than `GITHUB_TOKEN`) it is an error that cannot be waived; elsewhere it is a notice for now. In such a job the check also reads the text of the step for a runner word the command parser did not confirm (a quoted argument, a heredoc, a prose input), except in an `echo` or `printf` argument and in the pattern of a `grep`, `rg` or `sed`. `npm create`, `npm init <x>`, `pnpm create`, `yarn create` and `bun create` count as runners. It ships no package.
